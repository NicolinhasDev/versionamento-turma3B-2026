O versionamento de código é basicamente uma "máquina do tempo" ou um histórico de salvamento para os nossos arquivos de projeto.  Ao invés de ficarmos salvando várias cópias com nomes estranhos (tipo trabalho_v1, trabalho_final, agora_vai), utilizamos ferramentas como Git e GitHub para gerenciar as mudanças e colaborar sem que um sobrescreva o trabalho do outro. 

Abaixo estão algumas das nomenclaturas e comandos principais que me vêm à mente: 

Repositório: É a pasta principal que armazena todos os arquivos e o histórico do projeto. 

Commit (git commit): É como se você estivesse dando um "salvar jogo" (savegame) ou capturando uma imagem do código exatamente como está naquele momento. Sempre que há uma mudança, nós escrevemos uma mensagem explicando o que ocorreu.

Branch (Ramificação): É uma linha de desenvolvimento paralela. Permite adicionar novas funcionalidades ou realizar testes sem comprometer a versão principal do código (main ou master).

git push / git pull: push envia suas modificações locais para o repositório remoto (como o GitHub), enquanto pull obtém as atualizações do repositório para o seu computador.
